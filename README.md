# Тестовое задание для CityCar

## 1. Как бы я построил решение

Для начала сделал бы один Python-сервис: координатор запускает сбор данных, агент разбора звонков выделяет факты из разговора, агент-аналитик собирает отчёт. Получение данных и расчёт показателей оставил бы обычному коду. Для этого не нужны самостоятельные AI-агенты.

Из amoCRM сервис забирает сделки через `GET /api/v4/leads` и задачи через `GET /api/v4/tasks`, с OAuth-авторизацией и постраничной загрузкой. Из телефонии получает журнал звонков и записи через API провайдера. Название телефонии в задании не указано, поэтому конкретный метод нужно уточнить при подключении.

Записи расшифровывает ASR-модель, например Whisper. Агент разбора выделяет потребность клиента, возражения и договорённости, сохраняя цитаты и время в записи. Связывать звонки со сделками лучше по ID из интеграции; если остаётся только номер телефона, неоднозначные совпадения отправляются на проверку.

В отчёте показал бы новые и закрытые сделки за период, сумму успешных сделок, долю успешных среди закрытых, звонки и текущие просроченные задачи по менеджерам. Старые сделки, закрытые за эти 30 дней, тоже учитываются. Период фиксируется в часовом поясе компании; текущая просрочка выводится отдельно от результатов за месяц. Цифры считает код, LLM объясняет наблюдения и предлагает, что проверить. Рядом с выводом должна быть ссылка на сделку или фрагмент звонка.

Для хранения выбрал бы PostgreSQL: сделки, задачи, транскрипты и отчёты. Аудио — в закрытом S3-совместимом хранилище, если его разрешено копировать. Доступ по ролям, токены вне кода, сроки удаления записей согласуются с компанией.

## 2. Где нужен человек

Сбор, расчёты, расшифровка и черновик отчёта выполняются автоматически. Руководитель разбирает спорные выводы и принимает решения по сотрудникам. На первом этапе сервис ничего не меняет в CRM и не пишет клиентам.

Три основных риска:

1. Неполные данные: часть звонков не записалась или задачи ведутся вне CRM. В отчёте нужно показать, сколько звонков удалось обработать и связать со сделками, а не делать выводы по отсутствующим данным.
2. Ошибки распознавания и LLM. Выводы проверяются по цитатам и записи; подозрительные случаи идут человеку. Текст разговора считаю данными, а не инструкциями для агента.
3. Утечка клиентских данных. Во внешнюю модель нельзя отправлять записи без согласования. Нужны ограничение доступа, удаление лишних персональных данных и утверждённые сроки хранения.

## 3. Код

[amo_followup.py](amo_followup.py) — фрагмент до 50 строк. Он возвращает сделки, созданные за последние 30 дней, без привязанных задач либо с просроченными незавершёнными задачами. Здесь «без задач» означает, что нет задач вообще: сделка только с выполненными задачами в эту категорию не попадает. Учитываются задачи, привязанные непосредственно к сделке.

Это отдельная проверка, а не весь месячный отчёт. Пример читает все страницы задач, включая старые. Для большого аккаунта добавил бы более узкую выборку и кеширование, обработку 429 с повтором и обновление OAuth-токена. Права интеграции должны позволять видеть все нужные сделки и задачи.

Запуск: установить `requests` из `requirements.txt`, задать `AMO_BASE_URL` вида `https://<аккаунт>.amocrm.ru` и действующий `AMO_TOKEN`, затем выполнить `python3 amo_followup.py`. Токен не нужно сохранять в репозитории.

Проверки: `python3 -m unittest -v`. Тесты используют искусственные ответы API, без доступа к CRM. Есть проверки пагинации, пустого ответа, HTTP-ошибки и отбора задач. На реальном аккаунте этот пример пока не проверялся.

Документация amoCRM: [сделки](https://amocrm.ru/developers/content/crm_platform/leads-api), [задачи](https://amocrm.ru/developers/content/crm_platform/tasks-api).

## 4. Мой опыт

В МФО работал над подключением AI-агента к данным компании. Данные из внутренней БД собирались через Apache Airflow, затем загружались в amoCRM. Я настраивал работу агента и его доступ к этим данным; использовалась локальная модель Qwen.

В итоге агент был подключён к данным компании. Это результат моей части работы; цифры по экономии времени или бизнес-эффекту здесь не привожу. Название компании, содержимое данных и детали реализации остаются конфиденциальными.
